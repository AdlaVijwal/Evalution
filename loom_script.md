### Part 2: Architecture & Design Choices (3:00 – 6:30)
**[Screen: Show `README.md` Mermaid diagrams or architecture flowchart]**

* **Explain the Cyclic State Machine:**  
  *"Let's look at the system architecture. I implemented this using **LangGraph** as a cyclic state machine. Why LangGraph? Because unlike a linear chain, a production quality loop requires explicit conditional routing, state checkpointing, and guaranteed termination bounds."*

* **The Dual-Engine Evaluator:**  
  *"To judge the content, I built a **Dual-Engine Evaluator** that enforces 6 hard pass/fail checkpoints with **ZERO partial credit**.*  
  *1. Accuracy and Grounding (LLM Judge)*  
  *2. Beginner-Friendly Vocabulary (Deterministic Flesch-Kincaid grade $\le 8.5$)*  
  *3. Teaches by Example (LLM Judge checking for continuous Indian everyday analogies)*  
  *4. Clear, No Unexplained Jargon (Deterministic regex scanner)*  
  *5. Covers Key Points (What it is, Why it matters, How it works)*  
  *6. Coherent Teaching Flow (LLM Judge for pedagogical progression)*  

* **Why Dual-Engine? (Key Trade-off):**  
  *"Why did I combine deterministic Python code with an LLM judge? Because LLMs are notoriously fuzzy at counting syllables, sentence lengths, or guaranteeing that a specific term like 'cosine similarity' didn't slip through. By using deterministic static analysis for readability and forbidden jargon, we achieve **zero-hallucination verification** on the rules, reserving the LLM judge for semantic nuance."*

* **Guaranteed Loop Termination:**  
  *"The loop enforces a hard retry cap of `MAX_RETRIES = 2`. If a draft doesn't pass after two regeneration attempts, the system halts cleanly and dumps a diagnostic trace. It can never run into an infinite cycle."*
